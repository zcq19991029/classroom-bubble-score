# 课堂气泡系统维护

## 数据与权限底线

- 生产权威链路是 Sites Worker + D1 绑定 `DB`；浏览器缓存只作设备级回退，Supabase 仅保留为兼容/迁移用途，不能把它或页面显示当作当前权威数据。
- 只有所有者管理员可以生成一次性邀请码；邀请码有效期 24 小时、只能使用一次、普通教师不可生成。
- D1 只保存邀请码哈希、创建者、过期时间、使用状态，不保存明文邀请码；明文只在生成后的当前界面短暂展示，不写日志、源码或备份。
- 姓名、头像文字、工号必须通过 Worker API 写入 D1；工号唯一。账号按钮和资料页的管理员标识必须来自线上教师记录，而不是默认文案或 localStorage。
- 不在日志、公开仓库或截图中输出密码、会话令牌、API key、完整学生名单或明文备份。

## D1 数据地图

- `teachers`：账号、邮箱/工号、密码哈希、显示名、头像文字、管理员标识。
- `sessions`：登录会话及过期状态。
- `workspaces`：按教师隔离的班级、成绩、考勤、课程进度和操作记录。
- `invite_codes`：邀请码哈希、创建者、过期时间、最大次数与已使用状态。
- `migration_audit`：迁移批次、来源、数量、校验和与结果。

## 诊断与修改顺序

1. 先记录实际 URL、版本标记和可复现错误；用 `/api/health`、D1 概览和受控查询确认线上状态，再看页面。
2. 读取当前 workspace 汇总（班级数、学生数、日志数、考勤数、课程进度），任何写入前保留快照；导入按班级合并，绝不无意覆盖兄弟班级。
3. 验证备份 JSON 的数组结构、日志求和、孤立日志和重复工号；迁移后对比 `migration_audit` 与 D1 实际行数。
4. 修复根因后再做窄兼容；考勤须覆盖已签到、未到原因、请假/早退和确认保存，不能只凭按钮颜色判定成功。
5. Worker 源码变更必须先构建 `dist/server/index.js`（或项目声明的等价发布产物），再按 Sites skill 发布并做线上验证。

## 验收重点

- 账号：邀请码过期/重复使用/错误码/普通教师越权均失败；确认后的教师能登录，旧教师仍能登录。
- 数据：刷新、换设备和换班级后读取同一 D1 数据；成绩等于操作日志净和；导入后旧班级仍存在。
- 发布：核对实际 HTML、版本文件、Worker API、D1 绑定和缓存破坏参数；“部署成功”本身不等于功能已上线。
- 视觉：检查窄屏与宽屏切换时头部、课次条和气泡区的稳定坐标，不能把状态文本换行误判成按钮缩放。
